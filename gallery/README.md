# Made with Prism

Curated native examples for the [startup gallery](../docs/interface/gallery/README.md), tracked by [#61](https://github.com/chrizpro/prism/issues/61). Models and preview images are hosted here and downloaded on demand; the app embeds only `catalog.json`.

Models and scripts are MIT licensed under the repository [license](../LICENSE). These are concept examples, not certified engineering designs. Claude created the camera lens, the Meridian orrery, the Fold tablet stand, the cardboard box and the lotus dish; Codex created the other initial studies through Prism's actual modeling API. The gallery covers Solid, Freeform, Surface/NURBS, Assembly and Sheet Metal construction.

## What is here

Models are grouped by the main Prism workflow they show, and the app's startup gallery lists them in sections in this order, three per section until expanded: Solid, Surface, Freeform, NURBS, Sheet Metal, Assembly, CAM, Mold, CAE, ECAD. A model is listed under **every** workflow in its Workflow field (`CAE / Solid` appears under both CAE and Solid, `Solid / Assembly` under Solid and Assembly); the catalog's **Workflow** field uses the same names, joined with " / " when a model combines several (for example `Freeform / Solid`). Use the names of the workspace tabs: Solid, Surface, NURBS, Freeform, Sheet Metal, Assembly, and later CAM, CAE or Render. `python gallery/update_catalog.py --check` fails if a model in `catalog.json` is missing from this index.

| Drawing | Combination wrench drawing (`wrench-drawing`), Maple serving board drawing (`serving-board-drawing`), Fold tablet stand drawing (`fold-stand-drawing`) |

Sheet-metal parts are plain silver and the cardboard box is brown corrugated board, so a model's colors say what it is made of. Building scripts live next to this file as `build_<name>.py`; each asserts the sizes and volumes it expects, so running one is also a quick check that the modeling tools still work.

## Extra files

A catalog entry can list `Extras` (an animation video, an exploded view image): give each a `Label` and a `FileName` placed in `gallery/extras/`, and `python gallery/update_catalog.py` fills in the URL, size and SHA-256. The app offers them in a dropdown on the model's card. The orrery's video was made from 48 frames of *Drive Joints* renders, encoded with `ffmpeg -stream_loop 1 -framerate 24 -i f%03d.png -c:v libx264 -pix_fmt yuv420p -crf 26 -movflags +faststart`.

## Updating the collection

1. Build and save a `.prism` model in Prism. Reopen it and inspect geometry, materials and appearance. Keep useful source curves/surfaces hidden in the document. Supply a reproducible script where possible.
2. Put it under `models/`, with a real viewport capture or Prism render under `previews/`. Previews should be no larger than 810 × 504, preferably on a light studio background. Do not use generated illustrations as model evidence.
3. Update the catalog entry: unique stable lowercase ID, description, actual construction workflow, author/license and minimum app version. Run `python gallery/update_catalog.py` to set raw-content URLs, exact byte lengths, SHA-256 hashes and content-specific preview revisions. `python gallery/update_catalog.py --check` verifies consistency without modifying files. For large files use GitHub Release download URLs instead of committing binaries and adapt the catalog publishing script accordingly.
4. Validate all entries and links, run maintained Gallery tests, record actual model evidence, and publish the content on `develop`. The catalog refreshes independently of app releases. No merge to `main` is needed for these direct raw-content URLs.

The cache is content-addressed. A changed model never replaces an already opened working copy. Delete or replace an entry to curate the next collection; existing user copies remain intact.

## Reproduce the new studies

The revised guitar builder accepts `--discovery <automation.json>` to target a running Prism session explicitly. Its silhouette uses tangent-aligned cubic spans for rounded bouts, a tighter waist and unequal horns. The owner requested this shape revision and a viewport screenshot on 2026-11-16; no render or CAM setup is needed to review it.

The owner-approved [wood studies (#132)](../docs/interface/gallery/README.md) are native design files without CAM setups: [Maple observatory](models/maple-observatory.prism), [Art Deco mantel clock](models/deco-mantel-clock.prism), and [Maple/walnut guitar body](models/maple-walnut-guitar.prism). `build_pavilion.py`, `build_deco_clock.py` and `build_guitar.py` use the actual MCP/cadkit bridge through `demo_session.py`. Their current discovery path is `artifacts/pavilion/automation.json`; point it at the desired running Prism session before reproducing them. Builders start a new document and save checkpoints under `artifacts/`. Walnut bitmap data is embedded, so the models open without external textures. Following the owner's 2026-11-16 instruction, delivery prioritizes native models with validity/save/reopen checks; no renderer or automated test suite was run. Catalog cards remain unpublished. The initial desktop capture returned empty images; the revised guitar now has actual viewport evidence from a fresh automation host, linked in the canonical gallery guide. The guitar has routing, comfort contours and a rear cover, with no neck, strings or bridge/pickup hardware. The clock hands and rear cover are static parts.

`python gallery/build_drawings.py --discovery <discovery.json> --svg-output <folder>` builds the three editable A3 drawings from the existing models ([#96](https://github.com/chrizpro/prism/issues/96)). Open a copy and choose **Drawing** to edit the sheet. Each sheet contains top, front and isometric views and three measured overall dimensions. The script saves and reopens each document, checks the complete sheet state and exports the SVG used for its preview.

`python gallery/build_relief_plaque.py --discovery <discovery.json>` builds the carved lotus plaque ([#86](https://github.com/chrizpro/prism/issues/86)): a 150 × 150 × 18 mm maple block, a CAM setup and one **Image Carve** operation (3 mm ball nose, 3 mm deep, 130 mm square) from `extras/relief-lotus.png`, which is also offered as a download. The file reopens on the CAM tab with Playback open. A real Prism render does not show toolpaths or reference pictures, so the preview is the plain block: **known gap**, as the carving is only visible in the app. `python gallery/build_mold.py --discovery <discovery.json>` builds the injection mold: a steel block around a cap-shaped part, made into two exploded halves with **Create Mold**; it asserts the halves' positions and that their volumes add up to the block minus the cap. Both reopen ready for the user to press the command's button. Illustrations only.

`python gallery/build_wrench.py --discovery <discovery.json>` builds the combination wrench and sets up its analyses ([#85](https://github.com/chrizpro/prism/issues/85)): an 8 mm plate with an angled 13 mm open end, a tapered handle and a hex box end, rounded corners, chrome-vanadium appearance. The file keeps five static studies (self weight, a 5 MPa hammer blow on the ring end, a 900 N cheater-pipe overload, 300 N through the box end and 300 N through the open end, which is active), a natural-frequency setup and a thermal setup, and reopens on the **Static** tab, so the user only presses Run. The script solves everything and asserts: load balance, torque cases elastic and the overload yielding, tripled force giving tripled displacement, six rising natural frequencies, the thermal extremes, and a fatigue verdict. Modal and thermal need CalculiX (`PRISM_CCX`). `--topology-check` also runs Generative on the saved file (about 8 minutes) and checks it keeps about half the block. `--render-only` reopens the saved model. Study results are not stored in the file. An illustration, not a certified tool design.

`python gallery/build_serving_board.py --discovery <discovery.json>` builds the maple serving board and its CNC plan ([#84](https://github.com/chrizpro/prism/issues/84)): a Solid body (R25 corners, a 4 mm juice well, a hand slot) and a saved CAM setup with four operations on a 6 mm wood end mill: face, pocket the well, pocket the slot through, and a tabbed profile. It asserts the volume, then runs Stock review and the design check and requires no gouges, rapid contacts or holder contacts. Building it exposed the three CAM bugs fixed beside it. `--render-only` reopens the saved model; `--no-render` skips the render. Decorative only: feeds and speeds are placeholders, so prove out any program on scrap.

`python gallery/build_lotus_dish.py --discovery <discovery.json>` builds the Lotus dish with the Fold tool ([#83](https://github.com/chrizpro/prism/issues/83)): a square base, four petals that rise 50° and curl back 30°, with trapezoid tips, a ring of holes and slots. The script computes the signed per-bend angles in Fold's bend order, and asserts that the folded volume matches its own flat pattern and that all 17 holes are in it. `--render-only` reopens the saved model; `--no-render` skips the render. Decorative only.

`python gallery/build_cardboard_box.py --discovery <discovery.json>` builds the cardboard box with the Fold tool ([#82](https://github.com/chrizpro/prism/issues/82)): one plus-shaped die-line sketch (base, four walls, and on the back wall a hinged lid and a front lip, with handle slots in the short walls) and one construction line per bend, folded in a single step with **Fixed region** set to the region over the sketch origin. Fold also lays out the die line beside the box. The script asserts the box's size from the board thickness and dimensions; Fold itself refuses overlapping flanges. `--render-only` reopens the saved model; `--no-render` skips the render. A concept model, not a packaging design.

`python gallery/build_sheetmetal.py --discovery <discovery.json>` builds Fold ([#80](https://github.com/chrizpro/prism/issues/80)), a one-piece sheet-metal tablet stand. It sketches the cross-section, makes the bends and hem with Flange, chamfers the corners, cuts 30 round vents and a cable hole through the bent body, and unfolds it with Flat Pattern beside the part. Each cut is checked against its expected volume and repeated reversed when the default direction points away from the metal ([#79](https://github.com/chrizpro/prism/issues/79)); it avoids slots and rounded corners, which Flat Pattern rejects ([#78](https://github.com/chrizpro/prism/issues/78)). The tablet is a scale placeholder. `--render-only` reopens the saved model; `--no-render` skips the render. The blank is shown beside the part, and no DXF is written. This is a visual and workflow study, not a tested product design.

`python gallery/build_orrery.py --discovery <discovery.json>` builds Meridian ([#74](https://github.com/chrizpro/prism/issues/74)), a geared brass orrery and Prism's first gallery assembly. The movement is modeled: involute spur gears (one spline per tooth flank, phased so every mesh seats a tooth in a gap), six nested orbit tubes on a stepped fixed arbor, a blued-steel layshaft with an ebony winding knob, and a two-stage idler that drives Saturn from Jupiter's tube. Each moving part has a revolute joint and the gear couplings use the modeled tooth counts, so **Assemble › Drive Joints** on *Revolute 1* turns every planet at its gear ratio: Mercury 4, Venus 62/38, Earth 1, Mars 35/65, Jupiter 12/138 and Saturn 12/138 × 42/84 × 56/70 per layshaft turn. The Moon follows Earth's arm at 37:3. Planet maps and the zodiac enamel are procedural images from `orrery_textures.py` (Pillow and numpy), embedded in the model. A lamp inside the frosted-glass sun makes it glow in renders. `--render-only` reopens the saved model to iterate the preview; `--no-render` skips the render. The orrery is a display piece: the ratios are approximations (Mercury 0.250 vs 0.241 years, Saturn 28.75 vs 29.46 years), the couplings are ideal (no tooth contact or friction) and planet sizes and distances are not to scale. The script creates each new solid with the finished solids hidden, because the automatic New body/Cut check measures exact distances to every visible solid and takes minutes next to many-toothed wheels.

`python gallery/build_racer.py --discovery <discovery.json>` builds Comet, the stylized open-wheel racer inspired by the owner's reference. It uses editable Freeform red bodywork and cockpit pieces, rounded solid tires/rims, blue wings, yellow endplates and native racing-number graphics. `--render-only` reopens the saved model to iterate its preview. This is a visual concept with intentionally simple chassis/axle connections and no functional vehicle engineering.

`python gallery/build_aircraft.py --discovery <discovery.json>` builds the Skylark light-aircraft concept through the same actual MCP bridge. Its Freeform fuselage, canopy and propeller remain editable; exact lofted wing/tail bodies retain hidden airfoil sections. `--render-only` reopens the saved model for camera/preview iteration without rebuilding geometry. The aircraft replaces the iron in the active catalog; the older iron assets remain archived here. The design is a visual concept, with no aerodynamic or flightworthiness validation.

Launch an isolated built desktop with a private `PRISM_AUTOMATION_DISCOVERY` and `PRISM_SETTINGS_FILE`, then run `python gallery/build_examples.py --discovery <discovery.json>`. The script finds the built MCP bridge in the normal Release or Debug output (with `artifacts/gallery/bin/Prism.Mcp.dll` as a fallback); it drives the real MCP stdio bridge and bundled Python `cadkit`, records the calls under `artifacts/gallery/`, saves/reopens each document and validates exact shapes or cage topology. It also renders each model at 960 × 540, 96 samples, six bounces, final denoising. `--only table|pendant|chair` selects one study. `finish_existing.py` refreshes the iron and duct's appearances/previews in the same way. Preview downscaling uses Pillow; modeling scripts use only the Python standard library and bundled cadkit.

`python gallery/build_bicycle.py` builds Aster Road through the actual MCP bridge. It is a static assembly with 242 named solids, a 1000 mm wheelbase, 680 mm tires and 28 spokes per wheel. Teal coachwork, tan sidewalls, disc brakes, drop bars, cranks and pedals are native geometry; the chain is a continuous swept envelope. Frame members, sprockets and mechanical connections are visual simplifications. [GAL-I011](../Prism.Tests/Integration/DesktopGalleryTests.cs) checks saved geometry/appearance and wheel placement. See the [canonical gallery guide](../docs/interface/gallery/README.md) for actual verification evidence.

`python gallery/build_bellavista.py` builds Bellavista 1964 through the actual MCP bridge, saving staged native checkpoints. It combines a section-lofted exact body with cut wheel openings, four rounded tires and detailed chrome wheels, a shaped Freeform roof, thin solid glass panels, chrome trim, a grille and quad lamps, and tan Freeform upholstery with a wood fascia and steering wheel. `--phase` and `--resume` allow staged work; `--discovery` selects an isolated app. This is an original period-inspired visual concept, with simplified cabin and hardware, without suspension/engine systems, animation or engineering validation. [GAL-I010](../Prism.Tests/Integration/DesktopGalleryTests.cs) checks saved geometry, appearances, four-wheel ground placement and tire/coachwork clearance. The [canonical guide](../docs/interface/gallery/README.md) records actual verification.

`python gallery/build_arc_lamp.py` recreates the owner-approved Arc desk lamp through MCP. A 180° Fold at 68 mm inside radius rolls the 1.5 mm shade, Flange adds its hems and stepped support, and Fold makes the relieved plinth. Eighteen radial slots remain in the shade development. Four named developments are stored hidden, arranged separately from the assembled lamp; show them in the browser to inspect them. The lamp includes simplified mounting hardware, a diffuser and three warm render lights. No Revolve is used. `--no-render` skips the preview; `--phase`/`--resume` support staged work, and `--discovery` selects an app instance. Build the current app/bridge before reproduction; `PRISM_EXE` and `PRISM_MCP` select custom binaries. [GAL-I013](../Prism.Tests/Integration/DesktopGalleryTests.cs), [sheet-metal checks](../Prism.Tests/Headless/SheetMetal/SheetMetalTests.cs), and the [canonical gallery guide](../docs/interface/gallery/README.md) record verification. This is a visual modeling study with simplified electrical and mounting details.

`python gallery/build_walnut_valet.py` builds the owner-approved #131 walnut valet: 300 × 210 × 32 mm, three spline pockets with R8 floors, rounded rims and five fan grooves. Its original walnut bitmap is embedded in the native model ([texture provenance](textures/README.md)). Run phases `geometry`, `cam`, then `finish --render`; the actual MCP bridge and a current desktop build are required. Four saved operations face, rough, ball-finish and profile with holding tabs. It opens in Stock Review: use a 1.8 mm grid, 8 mm holder, 40 mm flute/holder clearance length and 0.3 mm comparison tolerance, then Play removal. The playback is a stepped heightfield estimate, not machine simulation. [GAL-I014](../Prism.Tests/Integration/DesktopCncPatternGalleryTests.cs) verifies saved geometry, bitmap and fresh paths, stock reduction and actual timer playback. Its final review retains holding tabs and a conservative finishing band; no physical machining was performed.

`python gallery/build_ridge_wheel.py --phase all --render` builds Ridge through MCP: a revolved arc-section carcass, five 32-sector tread rows with beveled blocks and narrow modeled sipes, and a silver barrel, six split spokes with branch recesses, six lug bores/nuts and a hub cap. Actual Circular Pattern features remain in history. Phases and staged native checkpoints support recovery. The result is a static multi-solid visual study, with overlapping component joints rather than an engineered fused tire or certified wheel. [GAL-I015](../Prism.Tests/Integration/DesktopCncPatternGalleryTests.cs) checks valid solids, repeat counts/volumes, six real lug bores, retained pattern recipes and ground contact. [Canonical scope and evidence](../docs/interface/gallery/README.md).

Both builders share `demo_session.py`. Build the current Desktop into `artifacts/cnc-wheel/final-bin` and the MCP bridge, launch isolated apps with private discovery/settings, and use `PRISM_EXE` / `PRISM_MCP` for custom binaries. The wood builder uses `artifacts/cnc-wheel/automation.json`; the wheel builder uses `tire-automation.json` beside it. Wait for each launched app's PID to appear in its discovery file before starting a builder. These scripts do not publish the gallery.

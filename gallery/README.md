# Made with Prism

Curated native examples for the [startup gallery](../docs/interface/gallery/README.md), tracked by [#61](https://github.com/chrizpro/prism/issues/61). Models and preview images are hosted here and downloaded on demand; the app embeds only `catalog.json`.

Models and scripts are MIT licensed under the repository [license](../LICENSE). These are concept examples, not certified engineering designs. Claude created the camera lens, the Meridian orrery, the Fold tablet stand, the cardboard box and the lotus dish; Codex created the other initial studies through Prism's actual modeling API. The gallery covers Solid, Freeform, Surface/NURBS, Assembly and Sheet Metal construction.

## What is here

Models are grouped by the main Prism workflow they show, and the app's startup gallery lists them in sections in this order, three per section until expanded: Solid, Surface, Freeform, NURBS, Sheet Metal, Assembly, CAM, CAE, ECAD. A model is listed under **every** workflow in its Workflow field (`CAE / Solid` appears under both CAE and Solid, `Solid / Assembly` under Solid and Assembly); the catalog's **Workflow** field uses the same names, joined with " / " when a model combines several (for example `Freeform / Solid`). Use the names of the workspace tabs: Solid, Surface, NURBS, Freeform, Sheet Metal, Assembly, and later CAM, CAE or Render. `python gallery/update_catalog.py --check` fails if a model in `catalog.json` is missing from this index.

| Workflow | Models (catalog ID) |
| --- | --- |
| CAE / Solid | Combination wrench (`wrench`) |
| CAM / Solid | Maple serving board (`serving-board`) |
| Sheet Metal | Cardboard box (`cardboard-box`), Lotus dish (`lotus-dish`), Fold tablet stand (`fold-stand`) |
| Solid / Assembly | Meridian orrery (`meridian-orrery`) |
| Solid | Atelier side table (`atelier-table`), 50 mm camera lens (`camera-lens`) |
| Freeform / Solid | Comet number-one racer (`comet-racer`), Skylark light aircraft (`skylark-aircraft`), Cove lounge chair (`cove-chair`) |
| Freeform | Azure handled bottle (`azure-bottle`) |
| Surface / NURBS | Halo pendant (`halo-pendant`), Transition duct (`transition-duct`), Arc mouse (`arc-mouse`) |

Sheet-metal parts are plain silver and the cardboard box is brown corrugated board, so a model's colors say what it is made of. Building scripts live next to this file as `build_<name>.py`; each asserts the sizes and volumes it expects, so running one is also a quick check that the modeling tools still work.

## Extra files

A catalog entry can list `Extras` (an animation video, an exploded view image): give each a `Label` and a `FileName` placed in `gallery/extras/`, and `python gallery/update_catalog.py` fills in the URL, size and SHA-256. The app offers them in a dropdown on the model's card. The orrery's video was made from 48 frames of *Drive Joints* renders, encoded with `ffmpeg -stream_loop 1 -framerate 24 -i f%03d.png -c:v libx264 -pix_fmt yuv420p -crf 26 -movflags +faststart`.

## Updating the collection

1. Build and save a `.prism` model in Prism. Reopen it and inspect geometry, materials and appearance. Keep useful source curves/surfaces hidden in the document. Supply a reproducible script where possible.
2. Put it under `models/`, with a real viewport capture or Prism render under `previews/`. Previews should be no larger than 810 × 504, preferably on a light studio background. Do not use generated illustrations as model evidence.
3. Update the catalog entry: unique stable lowercase ID, description, actual construction workflow, author/license and minimum app version. Run `python gallery/update_catalog.py` to set raw-content URLs, exact byte lengths, SHA-256 hashes and content-specific preview revisions. `python gallery/update_catalog.py --check` verifies consistency without modifying files. For large files use GitHub Release download URLs instead of committing binaries and adapt the catalog publishing script accordingly.
4. Validate all entries and links, run maintained Gallery tests, record actual model evidence, and publish the content on `develop`. The catalog refreshes independently of app releases. No merge to `main` is needed for these direct raw-content URLs.

The cache is content-addressed. A changed model never replaces an already opened working copy. Delete or replace an entry to curate the next collection; existing user copies remain intact.

## Reproduce the new studies

`python gallery/build_wrench.py --discovery <discovery.json>` builds the combination wrench and sets up its static studies ([#85](https://github.com/chrizpro/prism/issues/85)): an 8 mm plate with an angled 13 mm open end, a tapered handle and a hex box end, rounded corners, chrome-vanadium appearance. Three load cases are saved in the file (300 N through the open end, 300 N through the box end, 900 N cheater-pipe overload) with the open-end case active, and the file reopens on the **Static** tab, so the user only presses Run. The script solves them, checks the load balance, that the torque cases stay elastic and the overload yields, and that tripling the force triples displacement. More analyses (modal, thermal, fatigue, topology, a hammer blow, self weight) are planned for this part. Study results are not stored in the file. `--render-only` reopens the saved model. An illustration, not a certified tool design.

`python gallery/build_serving_board.py --discovery <discovery.json>` builds the maple serving board and its CNC plan ([#84](https://github.com/chrizpro/prism/issues/84)): a Solid body (R25 corners, a 4 mm juice well, a hand slot) and a saved CAM setup with four operations on a 6 mm wood end mill: face, pocket the well, pocket the slot through, and a tabbed profile. It asserts the volume, then runs Stock review and the design check and requires no gouges, rapid contacts or holder contacts. Building it exposed the three CAM bugs fixed beside it. `--render-only` reopens the saved model; `--no-render` skips the render. Decorative only: feeds and speeds are placeholders, so prove out any program on scrap.

`python gallery/build_lotus_dish.py --discovery <discovery.json>` builds the Lotus dish with the Fold tool ([#83](https://github.com/chrizpro/prism/issues/83)): a square base, four petals that rise 50° and curl back 30°, with trapezoid tips, a ring of holes and slots. The script computes the signed per-bend angles in Fold's bend order, and asserts that the folded volume matches its own flat pattern and that all 17 holes are in it. `--render-only` reopens the saved model; `--no-render` skips the render. Decorative only.

`python gallery/build_cardboard_box.py --discovery <discovery.json>` builds the cardboard box with the Fold tool ([#82](https://github.com/chrizpro/prism/issues/82)): one plus-shaped die-line sketch (base, four walls, and on the back wall a hinged lid and a front lip, with handle slots in the short walls) and one construction line per bend, folded in a single step with **Fixed region** set to the region over the sketch origin. Fold also lays out the die line beside the box. The script asserts the box's size from the board thickness and dimensions; Fold itself refuses overlapping flanges. `--render-only` reopens the saved model; `--no-render` skips the render. A concept model, not a packaging design.

`python gallery/build_sheetmetal.py --discovery <discovery.json>` builds Fold ([#80](https://github.com/chrizpro/prism/issues/80)), a one-piece sheet-metal tablet stand. It sketches the cross-section, makes the bends and hem with Flange, chamfers the corners, cuts 30 round vents and a cable hole through the bent body, and unfolds it with Flat Pattern beside the part. Each cut is checked against its expected volume and repeated reversed when the default direction points away from the metal ([#79](https://github.com/chrizpro/prism/issues/79)); it avoids slots and rounded corners, which Flat Pattern rejects ([#78](https://github.com/chrizpro/prism/issues/78)). The tablet is a scale placeholder. `--render-only` reopens the saved model; `--no-render` skips the render. The blank is shown beside the part, and no DXF is written. This is a visual and workflow study, not a tested product design.

`python gallery/build_orrery.py --discovery <discovery.json>` builds Meridian ([#74](https://github.com/chrizpro/prism/issues/74)), a geared brass orrery and Prism's first gallery assembly. The movement is modeled: involute spur gears (one spline per tooth flank, phased so every mesh seats a tooth in a gap), six nested orbit tubes on a stepped fixed arbor, a blued-steel layshaft with an ebony winding knob, and a two-stage idler that drives Saturn from Jupiter's tube. Each moving part has a revolute joint and the gear couplings use the modeled tooth counts, so **Assemble › Drive Joints** on *Revolute 1* turns every planet at its gear ratio: Mercury 4, Venus 62/38, Earth 1, Mars 35/65, Jupiter 12/138 and Saturn 12/138 × 42/84 × 56/70 per layshaft turn. The Moon follows Earth's arm at 37:3. Planet maps and the zodiac enamel are procedural images from `orrery_textures.py` (Pillow and numpy), embedded in the model. A lamp inside the frosted-glass sun makes it glow in renders. `--render-only` reopens the saved model to iterate the preview; `--no-render` skips the render. The orrery is a display piece: the ratios are approximations (Mercury 0.250 vs 0.241 years, Saturn 28.75 vs 29.46 years), the couplings are ideal (no tooth contact or friction) and planet sizes and distances are not to scale. The script creates each new solid with the finished solids hidden, because the automatic New body/Cut check measures exact distances to every visible solid and takes minutes next to many-toothed wheels.

`python gallery/build_racer.py --discovery <discovery.json>` builds Comet, the stylized open-wheel racer inspired by the owner's reference. It uses editable Freeform red bodywork and cockpit pieces, rounded solid tires/rims, blue wings, yellow endplates and native racing-number graphics. `--render-only` reopens the saved model to iterate its preview. This is a visual concept with intentionally simple chassis/axle connections and no functional vehicle engineering.

`python gallery/build_aircraft.py --discovery <discovery.json>` builds the Skylark light-aircraft concept through the same actual MCP bridge. Its Freeform fuselage, canopy and propeller remain editable; exact lofted wing/tail bodies retain hidden airfoil sections. `--render-only` reopens the saved model for camera/preview iteration without rebuilding geometry. The aircraft replaces the iron in the active catalog; the older iron assets remain archived here. The design is a visual concept, with no aerodynamic or flightworthiness validation.

Launch an isolated built desktop with a private `PRISM_AUTOMATION_DISCOVERY` and `PRISM_SETTINGS_FILE`, then run `python gallery/build_examples.py --discovery <discovery.json>`. The script expects the built MCP bridge in `artifacts/gallery/bin/Prism.Mcp.dll`; it drives the real MCP stdio bridge and bundled Python `cadkit`, records the calls under `artifacts/gallery/`, saves/reopens each document and validates exact shapes or cage topology. It also renders each model at 960 × 540, 96 samples, six bounces, final denoising. `--only table|pendant|chair` selects one study. `finish_existing.py` refreshes the iron and duct's appearances/previews in the same way. Preview downscaling uses Pillow; modeling scripts use only the Python standard library and bundled cadkit.

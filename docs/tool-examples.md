# Tool assistance

Hover help and active-tool guidance have separate jobs and locations.

- **Hover a ribbon button:** after a short delay, a tooltip opens beside the pointer with the tool's purpose, steps, a tip and, for tools that change geometry, a before/after picture. **Every ribbon button resolves help written for that tool** (`ToolHelp.ForRibbon`), in this order: a topic keyed to that exact button (`Tab:icon|Label` or `icon|Label`, in `ToolHelpButtons.cs`), the command's own topic (`ToolHelp.ForCommand`), the tab's `ForButton` map, then the icon's topic **only when its title names the same tool**. Many unrelated tools share an icon (Untrim and Box, Sketch Trim and Surface Trim, Freeform Thicken and the primitives), so an icon alone never decides the card. Pictures are small illustrations built from kernel shapes and hand-made meshes (`ToolHelpPictures.cs`); a topic may borrow another tool's picture through `Picture`, with its own captions. Flat sketch pictures are turned to face the preview camera so horizontal and vertical read correctly, and help pictures keep the whole model framed instead of zooming to the highlight. App actions and view modes (files, scripts, camera presets, finishes, lights, toggles) set `NoPreview` and show text only. [HLP-H001](../Prism.Tests/Headless/Ribbon/RibbonHelpTests.cs) fails when a button's card names a different tool, HLP-H002 when a picture is missing or empty, HLP-H003 covers shared icons, HLP-H004 the camera-facing sketch pictures; [SOL-H089](../Prism.Tests/Headless/Solid/SolidRibbonTests.cs) fails if a ribbon button resolves no topic. Dropdown variants use the same behavior, and a split's card follows its current child.
- **Learn More:** every tool tooltip has this hyperlink, regardless of whether it has an in-app example. Until the website is published it shows “Online tool guides are coming soon.” Configure `ToolDocumentationBaseUrl` with the future per-tool guide base URL; links append the escaped stable tool ID.
- Disabled ribbon commands and disabled dropdown options can still show hover help; they cannot be run until their usual requirements are met.
- **Activate a tool:** the top-right viewport assistance shows the current instruction. It updates as inputs are chosen, when the active selection slot changes, or when a tool enters a temporary operation step. Sketch tools use their current drawing prompt. Hovering another tool leaves this guidance and the active operation untouched.
- **Dismiss:** leave the tool and tooltip to close hover help, or press Esc. F1, right-click **Show tool example**, and the command panel's **Show tool example** open the same tooltip. These never add example geometry to the viewport.

The examples use isolated OpenCascade shapes and the existing mesh renderer. They never add scene objects, move the working camera, or create undo history. The active command's own geometry preview continues to show the result of the user's selections.

`Prism/Help/ToolHelp.cs` holds the feature examples, the main topic map and `ForRibbon`; `ToolHelpModel.cs` adds the modeling, sketch, datum and utility topics (`FindModel`, `FindUi`); `ToolHelpButtons.cs` holds topics written for one button; `ToolHelpPictures.cs` builds the pictures for those. Base topic text on the button's ribbon description and the tool's own prompts. Match command types as well as icons: Sweep 2 rails shares the Sweep Surface icon but needs different instructions. `MainViewModel.ToolHelp.cs` supplies live instructions; the ribbon owns hover tooltips.

Run `dotnet run --project tests/Prism.ToolHelpTests` from the repository root. Checks cover the kernel examples, pointer placement, images in both themes, documentation links, hover isolation, live selection steps, and dismissal. Screenshots are written to `artifacts/tool-help-review`.
